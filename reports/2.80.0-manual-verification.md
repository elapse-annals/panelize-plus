# Panelize Link 2.80.0 手工验收清单

自动验证已覆盖：进度事件协议与去重、70% 阈值、AppKit 浮窗保留/单次前置/重新唤起恢复进度、盲测与未知总数显示、扩展页 E2E。

隔离实机验证已完成：真实扩展 + 原生宿主 + 新构建客户端在 Chrome for Testing 中完成标签页复用发送、最小化窗口恢复、弹窗新建发送，以及“AI 准备中：0/1”“正在打开 AI 面板…”“正在发送…”与结果文本的读取。详见 [2.80.0-live-verification.md](2.80.0-live-verification.md)。

以下场景依赖真实用户按键会话与系统前台切换，仍需手工确认。

前置：

```bash
./desktop/macos/Scripts/install.sh --browser chrome
```

重载扩展，开启「启用全局输入桥接」，打开 `Panelize Link.app` 一次。

## 1. 标签页模式

1. 模式设为标签页，打开 Chrome 与 Panelize，确认存在多面板标签页。
2. 将 Chrome 最小化，按全局快捷键唤出客户端，输入问题并发送。
3. 确认浏览器被前置（最小化窗口恢复），客户端浮窗仍在，状态依次显示“AI 准备中：x/y”→“正在发送…”。
4. 发送结果显示约 1.15 秒后浮窗收起。

## 2. 弹窗模式

1. 模式设为弹窗，重复发送。
2. 确认已有弹窗被复用而不是新建第二个；浏览器同样被前置。

## 3. 浮窗与焦点

1. 发送期间切换到其他应用：浮窗不关闭。
2. 成功结果停留期间切换到其他应用：浮窗不关闭。
3. 点击浮窗外部、按 `Esc`、按全局快捷键：均可收起。
4. 发送中收起浮窗后等待进度更新：不会重新打开；再次唤出时显示最新进度。
5. 连续快速发送两次：浏览器每个请求只前置一次，不反复抢焦点。

## 4. 兼容与失败

1. 用 2.79.x 扩展连接 2.80.0 客户端：显示通用等待，成功结果返回后前置浏览器。
2. 关闭浏览器或禁用桥接后发送：保留输入并显示错误。
3. 盲测模式下发送：只显示数量，不显示 AI 名称。
