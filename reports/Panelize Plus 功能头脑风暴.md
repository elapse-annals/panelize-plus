# 用接力和数据补缺，让多模型对比更省力

**已过滤**：面板完成状态徽标（已有 panel activity chips，d46007b）；按问题自动推荐 prompt mode（与 Auto 触发词 CL 2.24.0 重复）；云端同步或团队共享（违反无后端、本地数据约束）；超时后自动补发（重复消耗配额，与手动 Retry Failed 重复）；同一模型开多个会话做自我 MoA（可行性未验证，面板与登录态耦合，暂缓）。多面板广播、Prompt 库、历史、快捷键、深色模式属于同类标配，未列入。

## 2. Top 3 推荐

**接力（上下游）。** 它的价值最高，痛点来自真实工作流，且与已有的面板、Fill 和composer 注入机制接得上。MVP 做：采纳后出现「填入其他面板」，选目标面板，把答案和来源标题放进输入框，只支持纯文本，不自动发送。MVP 不做：不自动发送，不跨面板同步，不存全文，不做附件。验证方法：先用一周手工日记，记录你把答案复制到别的模型的次数，作为基线；上线后比较「填入次数 / 采纳轮次」，若比值超过 0.2（推测阈值），且被填入面板的采纳率不低于平均，说明有用。

**额度受限面板默认跳过（提效）。** 成本最低，直接减少浪费，且数据已经有了。MVP 做：新一轮开始时，标记为 limited 或 quota 的面板默认取消勾选，可一键加回。MVP 不做：不自动识别额度，不显示剩余额度数字，因为没有可靠的数据源。验证方法：对比被标记面板的超时记录（`answer-stats` 已有超时计数）。若跳过后这类超时下降，或用户手动加回的比例低于 20%（推测阈值），说明默认设置合理。

**轮次补存 tier 与 prompt mode（信息缺口）。** 它是后续做「按模式路由」的前提，且只需加字段。MVP 做：`createRound` 增加 tier、mode 两个字段，老数据留空；统计页加一个筛选。MVP 不做：不加成本或 token 统计，不做新图表。验证方法：积累 2–3 周后，对同一模型比较 Deep 与默认模式的采纳率，每组至少 5 轮；差异超过约 15 个百分点（推测阈值）才值得继续做路由。

## 3. 最不该做的方向：自动裁判并自动采纳最佳答案

这件事看起来省事，实际有三重问题。第一，LLM 裁判有自偏好，GPT-4 类模型会给低困惑度（更像自己写的）文本打更高分（[Wataoka et al., arXiv 2410.21819](https://arxiv.org/abs/2410.21819)），位置偏差和冗长偏差也有文献记录（[arXiv 2411.15594](https://arxiv.org/pdf/2411.15594)）。本项目的 AI 摘要已经给出 verdict，若再自动选「最佳」，偏差会被当成结论。第二，采纳是统计里唯一的显式标签（+5 / -5），自动采纳会让统计自我确认，进而污染「最常用」排序和分类最佳芯片。第三，它依赖用户配置的 API，与 README 中「Free · No API keys」的承诺冲突，也受 provider 页面变化影响。

**注意**：以上依据来自只读盘点，未运行测试或加载扩展。2.43–2.47 为未提交的工作区改动，相关结论可能随之变化。
